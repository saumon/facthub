# API Contract: GET /api/facts/next

**Phase**: 1 — Design  
**Date**: 2026-05-24  
**Branch**: `002-next-fact-client`

---

## Endpoint

| Property | Value |
| -------- | ----- |
| **Method** | `GET` |
| **Path** | `/api/facts/next` |
| **Authentication** | None beyond a valid `client_id` query parameter |
| **Query parameter** | `client_id` (required, string, generated opaque client identifier) |
| **Request body** | None |
| **Content-Type (response)** | `application/json` |

---

## Query Parameters

| Name | Type | Required | Description |
| ---- | ---- | -------- | ----------- |
| `client_id` | string | Yes | Opaque identifier of an eligible client generated by the admin interface |

---

## Success Response — 200 OK

Returned when the client exists and at least one fact is available to serve.

**Body**:

```json
{
  "id": 2,
  "body": "Bananas are berries, but strawberries are not."
}
```

**Field descriptions**:

| Field | Type | Description |
| ----- | ---- | ----------- |
| `id` | integer | Identifier of the fact served for this request |
| `body` | string | Non-empty fact text |

---

## Bad Request Response — 400 Bad Request

Returned when `client_id` is missing or blank.

**Body**:

```json
{
  "error": "missing_client_id",
  "message": "client_id is required."
}
```

---

## Not Found Response — 404 Not Found (Unknown Client)

Returned when `client_id` does not correspond to an eligible client, including deleted clients.

**Body**:

```json
{
  "error": "unknown_client",
  "message": "No eligible client matches the provided client_id."
}
```

---

## Not Found Response — 404 Not Found (No Facts Available)

Returned when the client exists but no fact is currently available to serve.

**Body**:

```json
{
  "error": "no_facts_available",
  "message": "No fun facts are currently available."
}
```

---

## Behaviour Notes

- Facts are served in ascending fact id order for a given client.
- Each client has an independent cursor; one client never advances another client's sequence.
- After the highest available fact id is served, the next successful call wraps to the lowest available fact id.
- Newly created facts become immediately eligible at their canonical position without resetting existing clients.
- If the fact referenced by the stored cursor has been deleted, the next call continues from the next available fact id greater than that cursor, or wraps if none exists.
- The endpoint does not require any secret beyond `client_id` in this feature scope.
- When two requests for the same client are processed concurrently and enough facts are available, they must return distinct consecutive facts.

## Example cURL

```bash
# Success
curl -s "https://example.com/api/facts/next?client_id=4f3c7f5d8d7a4c5e9a7b3d2c1e0f9a8b"

# Missing client_id
curl -s -o /dev/null -w "%{http_code}" "https://example.com/api/facts/next"
# → 400

# Unknown client
curl -s -o /dev/null -w "%{http_code}" "https://example.com/api/facts/next?client_id=unknown"
# → 404
```
